# คำอธิบายการปรับปรุงระบบ Chunking และการดึงข้อมูลตาราง (RAG Architecture Updates)

เอกสารนี้อธิบายการปรับปรุงสถาปัตยกรรม 3 ประการในระบบ [chunk.py](file:///z:/Intern/2026/มวล/PJChatbot/Admin/chunk.py) และ [server.py](file:///z:/Intern/2026/มวล/PJChatbot/user/backend/server.py) เพื่อเพิ่มประสิทธิภาพและความแม่นยำในการค้นหาและตอบคำถามภาษาไทย

---

### 1. แก้ปัญหาตารางขาดบริบท (Table Context Isolation)
*   **ปัญหาเดิม**: เมื่อแยกตารางออกมาเป็นบล็อกอิสระ ตารางจะไม่มีคำอธิบายหรือหัวข้อกำกับ ทำให้โมเดล RAG และ Vector Search ขาดการยึดโยงว่าตารางนี้กำลังพูดถึงเรื่องอะไร (เช่น ตารางอัตราค่ารักษาของตำแหน่งอะไร หรือแผนกไหน)
*   **แนวทางแก้ไข (ใน `chunk.py`)**: 
    - เพิ่มระบบ **Heading Tracking** ในฟังก์ชัน `parse_blocks` โดยการวนอ่านเอกสารทีละบรรทัด หากพบบรรทัดที่เป็นหัวข้อหลัก (บรรทัดขึ้นต้นด้วย `#`, `##` หรือ `###` ยกเว้นแถวระบุเลขหน้า) ระบบจะจำหัวข้อนั้นเก็บไว้ในตัวแปร `current_heading`
    - เมื่อสร้างบล็อกตาราง (`type: 'table'`) ระบบจะส่งหัวข้อล่าสุดนี้กำกับไปด้วย และนำมาประกบไว้ที่บรรทัดบนสุดของข้อความตาราง (`raw_table_with_heading`) ก่อนบันทึกข้อมูล ทำให้ตารางนั้นๆ มีความหมายผูกพันกับหมวดหมู่หัวข้ออยู่เสมอ

---

### 2. แก้ปัญหาการหั่นครึ่งคำภาษาไทย (Thai Word Splitting)
*   **ปัญหาเดิม**: `RecursiveCharacterTextSplitter` ใช้ตัวแยกข้อความเริ่มต้นที่มีสตริงว่าง `""` อยู่ท้ายสุด ซึ่งหากตัวแบ่งด้านบนไม่สามารถหั่นข้อความให้เล็กลงตามขนาด `chunk_size` ได้ มันจะสับแบ่งรายตัวอักษรทันที ส่งผลให้คำภาษาไทยโดนตัดแบ่งครึ่งคำ (เช่น "โรงพยา\nบาล") ซึ่งทำลายความสามารถในการทำ Embedding และการค้นหา
*   **แนวทางแก้ไข (ใน `chunk.py`)**:
    - ปรับชุด `separators` ของ LangChain ใหม่เป็น `["\n\n", "\n", " "]` โดย **นำสตริงว่าง `""` ออก** ทำให้การหั่นตัวอักษรหยุดทำงาน และบังคับให้หั่นได้ย่อยที่สุดที่ช่องว่าง `" "` เท่านั้น
    - นำ **`sent_tokenize` จากโมดูล `pythainlp`** เข้ามาช่วยทำ Pre-processing โดยนำข้อความในบล็อกธรรมดามาซอยย่อยเป็นประโยคภาษาไทยที่สมบูรณ์ แล้วเชื่อมกลับเข้าด้วยกันด้วยช่องว่าง `" "` ทำให้เรามั่นใจว่าทุกประโยคจะมีช่องว่างคั่นกลาง และ LangChain จะสามารถแบ่งประโยคได้อย่างเป็นธรรมชาติโดยไม่มีทางตัดกลางคำภาษาไทย

---

### 3. สถาปัตยกรรม Parent-Child สำหรับตาราง (Markdown Table Parent-Child)
*   **ปัญหาเดิม**: ตาราง Markdown ที่มีตัวอักษร โครงสร้างขีด และเครื่องหมายท่อส่งข้อมูล (`|`) ซับซ้อน หากแปลงเป็นเวกเตอร์ตรงๆ จะให้ค่าความคล้ายคลึง (Similarity) ที่ต่ำมาก และมักค้นหาไม่พบ หรือหากดึงมาได้ก็มีความยาวเกินและทำให้บริบทปะปน
*   **แนวทางแก้ไข (ใน `chunk.py` และ `server.py`)**:
    - **การทำดัชนี (Child -ใน `chunk.py`)**: เมื่อพบบล็อกตาราง ระบบจะไม่นำตารางดิบมาทำเวกเตอร์ แต่จะสร้างข้อความสรุปกระชับแทนผ่านฟังก์ชัน `generate_table_description` (เช่น ดึงหัวข้อเรื่องรวมถึงดึงหัวคอลัมน์ของตารางมาสร้างเป็นข้อความอธิบายแบบอ่านง่าย) และบันทึกลงในฟิลด์ `content` เพื่อให้เวกเตอร์สแกนหาคำศัพท์ได้ตรงจุด
    - **การจัดเก็บข้อมูลจริง (Parent -ใน `chunk.py`)**: ย้ายโครงสร้างตารางเต็มรูปแบบที่จัดฟอร์แมตสะอาดแล้ว ไปเก็บไว้ในออบเจกต์ `metadata["raw_table"]` แทน
    - **การสืบค้นข้อมูลป้อน LLM (Retrieval -ใน `server.py`)**: ปรับปรุงโค้ดฝั่ง Backend ให้ตรวจสอบผลการสืบค้น หากพบบล็อกประเภทตาราง (`type == 'table'`) และพบข้อมูล `"raw_table"` ใน metadata ระบบจะสลับดึงตารางตัวเต็ม (Parent) ไปป้อนให้แก่ LLM (Qwen/Llama) ทำการอ่านวิเคราะห์แทนคำอธิบายย่อยทันที ส่งผลให้บอทตอบคำถามข้อมูลสถิติจากตารางได้อย่างครบถ้วนและแม่นยำสูงสุด
