1.2 Backend/alembic.ini และ Backend/alembic/

ระบบควบคุมเวอร์ชันของโครงสร้างฐานข้อมูล (Database Schema Version Control)

Backend/alembic/env.py & alembic.ini Database Migration Engine

การทำงานของโค้ด:

  • config.set_main_option("sqlalchemy.url", settings.DATABASE_URL_SYNC): ดึงค่า Database URL อัตโนมัติจาก app.core.config.settings โดยไม่ต้อง Hardcode รหัสผ่านลงใน alembic.ini

  • run_migrations_online(): รัน Migration ภายใต้ Transaction เพื่อรับประกันว่าหากเกิดข้อผิดพลาด ระบบจะ Rollback อัตโนมัติ
ความสำคัญ: ทำให้การอัปเกรดฐานข้อมูลบน Server จริงมีประวัติที่ตรวจสอบได้ (Audit Trail) และไม่มีปัญหาข้อมูลสูญหายจากการ Drop Table ผิดพลาด

2. ฟังก์ชัน lifespan(app: FastAPI) (บรรทัดที่ 38-68)

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup Phase
    logger.info("🚀 %s v%s starting...", settings.APP_NAME, settings.APP_VERSION)
    await create_tables()        # 1. ตรวจสอบตารางฐานข้อมูล
    await init_default_admin()    # 2. สร้าง Admin คนแรกหากระบบว่างเปล่า
    try:
        from app.services.rag_service import load_retriever
        load_retriever()          # 3. Warm-up โหลดโมเดล AI และ ChromaDB เข้า RAM
    except Exception as e:
        logger.warning("⚠️ RAG Retriever not loaded: %s", e)
    yield
    # Shutdown Phase
    logger.info("👋 %s shutting down...", settings.APP_NAME)

คำอธิบาย: จัดการ Lifecycle ตอนเริ่มและหยุดแอป โดย Warm-up โหลดโมเดล BGE-M3 และดัชนีเข้าหน่วยความจำทันที ทำให้ผู้ใช้ที่แชทคนแรกไม่ต้องรอโหลดโมเดล 10-20 วินาที

4. CORS Middleware & Subnet Regex (บรรทัดที่ 130-162)

_octet = r"(?:25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])"

2.3 Backend/app/core/database.py

ระบบเชื่อมต่อและจัดการ Connection Pool กับฐานข้อมูล TiDB Cloud

Async Database Engine & Dependency SQLAlchemy Async

ฟังก์ชันสำคัญ:

  • create_async_engine(...): สร้าง Engine พร้อมตั้งค่า pool_size=10, max_overflow=20, pool_pre_ping=True (ตรวจสอบว่า Connection ยังไม่หลุดก่อนส่งให้คำขอ) และบังคับเปิด ssl: True สำหรับ TiDB Serverless
  • async def get_db() -> AsyncGenerator[AsyncSession, None]: 
    async with AsyncSessionLocal() as session:
    try:
        yield session
        await session.commit()
    except Exception:
        await session.rollback()
        raise
    finally:
        await session.close()
    FastAPI Dependency สำหรับจ่าย Session ให้กับแต่ละ Request เมื่อประมวลผลเสร็จจะ Commit อัตโนมัติ หากเกิดข้อผิดพลาดจะ Rollback ทันที ป้องกันปัญหา Transaction ค้าง

2.4 Backend/app/core/security.py

โมดูลความปลอดภัย การเข้ารหัส และการป้องกันการโจมตีไฟล์ระบบ

Security & Cryptography Functions High Security Impact
ชื่อฟังก์ชัน การทำงานและตรรกะโค้ด ความสำคัญในการป้องกันภัยคุกคาม
hash_password(plain) สร้าง Salt และ Hash รหัสผ่านด้วย bcrypt.hashpw ป้องกันการดูรหัสผ่านจริงหากฐานข้อมูลรั่วไหล
verify_password(plain, hash) ตรวจสอบรหัสผ่านด้วย bcrypt.checkpw ตรวจสอบความถูกต้องโดยไม่ต้องถอดรหัส
create_access_token(data) สร้าง JWT Token ที่มีอายุ 15 นาที พร้อมระบุ type: access จำกัดอายุการใช้งาน ป้องกันการนำ Token เก่ามาใช้ซ้ำ
create_refresh_token(data) สร้าง JWT Token อายุ 7 วัน สำหรับขอ Access Token ใหม่ รักษา Session การล็อกอินอย่างปลอดภัย
safe_path(base_dir, user_path) ใช้ is_relative_to() และ Path.parents ตรวจสอบว่า Path ผลลัพธ์ต้องอยู่ภายใต้ base_dir เท่านั้น ป้องกัน Path Traversal Attack (CWE-22) ไม่ให้ผู้ใช้ป้อน ../../windows/win.ini หรือชื่อไฟล์หลุดโฟลเดอร์
safe_filename(filename) ตัด Path Delimiter (/, \) ออกทั้งหมด เหลือเฉพาะ Base Name ป้องกันการตั้งชื่อไฟล์อัปโหลดที่แฝง Path Directory

2.5 Backend/app/core/rate_limit.py

ระบบป้องกัน DoS และจำกัดความถี่การยิงคำขอ (Sliding Window Algorithm)

class RateLimiter Traffic Controller

การทำงานของโค้ด:

  • ใช้ collections.deque บันทึก Timestamp ของแต่ละ Request แยกตาม IP Address
  • ฟังก์ชัน is_rate_limited(ip, max_requests, window_seconds):
    1. ลบ Timestamp เก่าที่อยู่นอกหน้าต่างเวลา (เช่น เกิน 60 วินาทีที่แล้ว) ออกจากคิว
    2. นับจำนวน Request ที่เหลืออยู่ในคิว หากเกิน max_requests จะคืนค่า True (ถูกบล็อก)
    3. หากไม่เกิน จะเพิ่มเวลาปัจจุบันเข้าคิวและอนุญาตให้ทำงานต่อ
  • มีฟังก์ชัน Cleanup ลบ IP ที่ไม่มีการเคลื่อนไหวออกจากหน่วยความจำอัตโนมัติเพื่อป้องกัน Memory Leak
ความสำคัญ: ปกป้องระบบจากการถูกสแปมคำถาม และควบคุมค่าใช้จ่าย API ของ LLM ไม่ให้บานปลาย

(feedback)		 id, rating (like/dislike), stars (1-5), comment, query, answer, history_id เก็บบันทึกคะแนนความพึงพอใจและเหตุผลการ Dislike เชื่อม FK กับ history.id
UnansweredQuery
(unanswered)		 id, query, count, status (Pending/Resolved), timestamp เก็บบันทึกคำถามที่บอทหาคำตอบไม่พบ พร้อมนับความถี่ที่ถูกถามซ้ำ
Form
(forms)		 id, name, filename, page, download_link เก็บรายการแบบฟอร์มคำขอสวัสดิการที่ตัดหน้า PDF ไว้ให้ดาวน์โหลด
Announcement
(announcements)		 id, title, content (HTML Sanitize), is_active, created_at เก็บประกาศและข่าวประชาสัมพันธ์สำหรับแสดงบน Pop-up หน้าเว็บ

3.2 Backend/app/schemas/schemas.py

เลเยอร์ Data Contract และ Data Validation ด้วย Pydantic

Schemas สำคัญสำหรับ Request / Response Validation Layer
  • ChatRequest: ตรวจสอบข้อมูลคำถามจากผู้ใช้ (query: str, session_id: Optional[str], history: Optional[List[Dict]])
  • ChatResponse: จัดรูปแบบคำตอบส่งกลับ (answer: str, references: List[ReferenceItem], response_time: float, session_id: str)
  • DocumentUpdate, DocumentResponse: จัดรูปแบบข้อมูลเอกสารและ Chunks
  • SystemSettingsUpdate: ตรวจสอบช่วงค่าของ Temperature (0.0 - 1.0) และ Max Tokens
  • FeedbackCreate: ตรวจสอบความถูกต้องของคะแนนดาว (1 - 5) หรือ Rating (like/dislike)
  • AdminUserCreate, AdminUserResponse: ตรวจสอบความยาวรหัสผ่าน และกรองไม่ส่ง password_hash กลับไปยัง Client
ความสำคัญ: ทำหน้าที่เป็นเกราะป้องกันข้อมูลผิดพลาด (Bad Request) ตั้งแต่ด่านหน้า ก่อนที่ข้อมูลจะเข้าสู่ระบบฐานข้อมูลหรือ Business Logic

4. Business Logic Services Layer (เลเยอร์ประมวลผลหลัก)

4.1 Backend/app/services/rag_service.py

หัวใจหลักของระบบ RAG (Retrieval-Augmented Generation) และการเชื่อมต่อ LLM

rag_service.py Functions Breakdown AI & Search Engine

1. load_retriever() / get_retriever()

คำอธิบาย: โหลดคลาส HybridRetriever จาก Admin/emb.py แบบ Singleton Pattern โหลดโมเดล BGE-M3 และ Index เข้า RAM เพียงครั้งเดียว

2. check_greeting(query: str) -> Optional[str]

คำอธิบาย: ตรวจสอบคำทักทายพื้นฐาน (เช่น "สวัสดี", "hello", "ดีครับ") หากพบจะส่งข้อความทักทายกลับทันทีโดยไม่ต้องส่งไปถาม LLM ช่วยประหยัดเวลาและลดการใช้ Token

3. check_inappropriate(query: str) -> bool

คำอธิบาย: กรองคำหยาบคายและข้อความที่ไม่เหมาะสมเบื้องต้น

4. query_rag(query, session_id, history, db) -> Dict[str, Any]

ขั้นตอนการทำงานแบบละเอียด:

  1. ดึงการตั้งค่า AI (System Prompt, Temperature, Model) จากตาราง settings
  2. เรียก retriever.search(query, top_k=settings.top_k) เพื่อค้นหาเนื้อหาที่เกี่ยวข้องด้วย Hybrid Search (ChromaDB + BM25 + Weighted RRF)
  3. รวบรวม Chunks ที่ค้นพบมาประกอบเป็น Context Block
  4. ส่งคำขอแบบ Async ผ่าน httpx.AsyncClient ไปยัง OpenRouter API ด้วยโมเดลที่กำหนด
  5. สกัดข้อมูลชื่อเอกสารและเลขหน้า PDF ที่ใช้อ้างอิง (references)
  6. บันทึกประวัติการแชทลงในตาราง history แบบ Async ทันที
  7. คืนค่า Response ให้ Router นำไปส่งกลับผู้ใช้
ความสำคัญ: เป็นแกนหลักที่ทำให้ผู้ใช้งานได้รับคำตอบที่ถูกต้องตามระเบียบสวัสดิการของโรงพยาบาล พร้อมลิงก์เปิดหน้า PDF ต้นฉบับได้อย่างแม่นยำ

4.2 Backend/app/services/document_service.py

ระบบจัดการวงจรชีวิตเอกสาร (Document Processing Pipeline)

document_service.py Functions Document Engine
  • process_uploaded_document(...): รับไฟล์ PDF จากแอดมิน, ใช้ PyMuPDF อ่านข้อความทีละหน้า, ส่งไปทำความสะอาดตัดอักขระขยะผ่าน cleanData.py, และตัด Chunks ด้วย RecursiveCharacterTextSplitter
  • approve_document_pipeline(doc_id, chunks, db): บันทึก Chunks ที่แอดมินตรวจสอบและแก้ไขแล้วลงในไฟล์ sample_chunks.json และปรับสถานะเอกสารเป็น Active
  • delete_document_service(doc_id, db): ลบไฟล์ต้นฉบับในโฟลเดอร์ uploads/, ลบข้อมูลในฐานข้อมูล, และสั่งลบ Vector ออกจาก Index ทันที

4.3 Backend/app/services/rebuild_service.py

ระบบสร้างดัชนีค้นหาใหม่ในเบื้องหลัง (Background Vector Rebuilding)

rebuild_service.py Functions Index Synchronizer

การทำงาน: รันฟังก์ชัน rebuild_db.py ใน Background Thread เพื่อสร้าง ChromaDB Collection ใหม่และคำนวณตาราง BM25 ใหม่ทั้งหมด โดยจะอัปเดตสถานะ rebuild_status: processing -> success/failed ลงในฐานข้อมูล ทำให้แอดมินสามารถเปิดดูความคืบหน้าได้ตลอดเวลา

4.4 Backend/app/services/unanswered_service.py & feedback_service.py

ระบบรวบรวมคำถามที่ตอบไม่ได้และวิเคราะห์ความพึงพอใจ

Analytics & Continuous Improvement Feedback Services
  • record_unanswered_query(query, db): บันทึกคำถามที่บอทหาเอกสารไม่พบ หากมีคำถามเดิมซ้ำจะบวกค่า count += 1 แทนการสร้างแถวใหม่ ช่วยจัดอันดับปัญหาที่ถูกถามบ่อย
  • record_feedback(rating, stars, comment, history_id, db): บันทึกคะแนน CSAT (1-5 ดาว) หรือการกด Dislike พร้อมเชื่อมโยงกับบทสนทนาในอดีต
