1. ภาพรวมกระบวนการประมวลผลข้อมูล (Pipeline Overview)

ระบบจัดการข้อมูลของ TUH Chatbot AI แบ่งออกเป็น 3 ไปป์ไลน์หลัก ที่ทำงานประสานกันอย่างมีระบบ:

ไปป์ไลน์ (Pipeline) โมดูลที่รับผิดชอบ หน้าที่และเป้าหมายหลัก
1. Document & Text Pipeline admin_documents.py
document_service.py
Admin/cleanData.py		 รับไฟล์ PDF สวัสดิการ สกัดข้อความดิบ คลีนข้อความภาษาไทย แปลงเลขไทย และแบ่งเป็น Chunks ย่อย
2. Indexing & Vectorization rebuild_service.py
Admin/emb.py
Admin/rebuild_db.py		 แปลง Chunks ที่อนุมัติแล้วให้เป็น Dense Vector (BGE-M3) และสร้าง BM25 Lexical Keyword Index
3. HTML Sanitization Pipeline Backend/app/utils/sanitize.py ทำความสะอาดโค้ด HTML จาก Rich Text Editor ป้องกัน Stored XSS ในข่าวประชาสัมพันธ์

2. โพรเซสการประมวลผลเอกสารและการคลีนข้อมูล (Step-by-Step)

STEP 1 การอัปโหลดไฟล์ PDF และตรวจสอบความปลอดภัย
admin_documents.py

กระบวนการทำงาน:

  1. ผู้ดูแลระบบอัปโหลดไฟล์ PDF สวัสดิการผ่านหน้า AdminWeb
  2. ระบบเรียกฟังก์ชัน safe_filename(file.filename) ตัด Path Delimiters (/, \) ออก เพื่อป้องกันการตั้งชื่อไฟล์ที่แฝง Path Traversal
  3. บันทึกไฟล์ต้นฉบับลงโฟลเดอร์ uploads/[filename].pdf
  4. สร้างเรคอร์ดลงตาราง documents ในสถานะ status = "Processing"
STEP 2 การสกัดข้อความดิบรายหน้า (Raw Text Extraction)
document_service.py / PyMuPDF

กระบวนการทำงาน:

  1. ใช้ไลบรารี PyMuPDF (fitz) เปิดอ่านไฟล์ PDF ทีละหน้า
  2. สกัดข้อความ Text พร้อมใส่ Marker กำกับเลขหน้า เช่น # Page 1 [ข้อความในหน้า 1]...
  3. บันทึกไฟล์ข้อความดิบลงใน uploads/[filename].raw.txt
  4. อัปเดตสถานะเอกสารเป็น status = "Step_Raw_Text"
# โค้ดสกัดข้อความรายหน้า
doc = fitz.open(pdf_path)
raw_text = ""
for page_num, page in enumerate(doc):
    raw_text += f"
# Page {page_num + 1}
" + page.get_text()
STEP 3 การคลีนและทำความสะอาดข้อมูลภาษาไทย (Thai Text Normalization)
Admin/cleanData.py

ตรรกะการคลีนข้อมูล 4 ขั้นตอน:

กฎการคลีน (Rule) ตัวอย่างข้อมูลก่อนคลีน ผลลัพธ์หลังคลีน
1. แปลงเลขไทยเป็นอารบิก
replace_thai_numbers()		 เบิกได้ไม่เกิน ๕,๐๐๐ บาท ในข้อ ๑๒ เบิกได้ไม่เกิน 5,000 บาท ในข้อ 12
2. ซ่อมสระอำแตก/วรรณยุกต์ลอย
re.sub(r'([ก-ฮ][่้๊๋]?)\s+า', r'ำ')		 น ้า , ประจ า , ท าการ น้ำ , ประจำ , ทำการ
3. กรองหน้าที่ยกเว้น
exclude_pages = [1, 2]		 หน้า 1 (หน้าปก), หน้า 2 (คำนำ) ตัดทิ้งทั้ง Block ไม่นำมาประมวลผล
4. ตัด Whitespace ซ้ำซ้อน ระเบียบ สวัสดิการ ระเบียบ สวัสดิการ

เมื่อคลีนเสร็จ บันทึกไฟล์เป็น uploads/[filename].clean.txt และตั้งสถานะเป็น Step_Cleaned

STEP 4 การตัดแบ่งข้อความเป็นท่อนย่อย (Text Chunking)
LangChain Text Splitter

พารามิเตอร์การตัด Chunk:

  • chunk_size = 800 - 1000 ตัวอักษร (ขนาดที่พอดีต่อการทำ Embedding และไม่เกิน Context Window)
  • chunk_overlap = 150 ตัวอักษร (ช่วยรักษาความต่อเนื่องของประโยคระหว่างรอยต่อ)
  • Metadata Binding: แต่ละ Chunk จะถูกผูกกับ source (ชื่อไฟล์), page (เลขหน้า), และ chunk_id

บันทึก Chunks ลงไฟล์ sample_chunks.json และปรับสถานะเป็น Step_Chunk_Preview เพื่อให้แอดมินตรวจทานบนหน้าเว็บ

STEP 5 การตรวจทานและอนุมัติ (Admin Review & Approval)
AdminWeb Chunk Editor Grid

การทำงาน:

  1. แอดมินสามารถเปิดดู Chunks ทั้งหมด แก้ไขข้อความที่สแกนผิด หรือลบ Chunk ที่ไม่จำเป็นได้ผ่านหน้าเว็บ
  2. เมื่อกด "อนุมัติเอกสาร (Approve)" สถานะเอกสารจะเปลี่ยนเป็น Active
  3. ระบบจะสั่งรัน Background Rebuild Task เพื่อนำ Chunks เข้าสู่ Vector DB ทันที
STEP 6 การสร้างดัชนีค้นหาแบบผสมผสาน (Hybrid Vector & Lexical Indexing)
Admin/emb.py & rebuild_db.py

การประมวลผลดัชนี 2 รูปแบบพร้อมกัน:

  1. Dense Vector Embedding: รันโมเดล BAAI/bge-m3 สร้างเวกเตอร์ความหมายขนาด 1024 มิติ แล้วบันทึกลง ChromaDB
  2. Lexical Keyword Indexing: ใช้ PyThaiNLP (engine='newmm') ตัดคำภาษาไทยเพื่อสร้างตารางดัชนีคำของ BM25
  3. เมื่อ Indexing เสร็จสิ้น จะสั่ง reload_retriever() โหลดข้อมูลใหม่ขึ้น RAM พร้อมให้บริการแชททันที

3. โพรเซสการคลีนข้อมูล HTML เพื่อความปลอดภัย (XSS Sanitization)

การทำความสะอาดเนื้อหาประกาศข่าวสาร (sanitize_html)
Backend/app/utils/sanitize.py

หลักการทำงานของฟังก์ชัน sanitize_html:

ใช้ไลบรารี nh3 (Rust-based HTML Sanitizer ความเร็วและความปลอดภัยสูง) ทำการกรองเนื้อหาที่ส่งมาจาก CKEditor ก่อนบันทึกลงตาราง announcements

ประเภทความปลอดภัย สิ่งที่ระบบตรวจสอบและอนุญาต สิ่งที่ระบบตัดทิ้งทันที (Filtered Out)
HTML Tags <p>, <strong>, <em>, <u>, <ul>, <ol>, <li>, <a>, <table>, <tr>, <td>, <span> <script>, <iframe>, <object>, <embed>, <form>, <input>
Attributes href, target, style, colspan, rowspan Inline Event Handlers ทั้งหมด (onclick, onerror, onload, onmouseover)
URL Schemes http://, https://, mailto: javascript:, data:, vbscript:
Link Protection เพิ่ม rel="noopener noreferrer" อัตโนมัติ ป้องกัน Tabnabbing Attack จากลิงก์ภายนอก

4. โพรเซสการสืบค้นและสร้างคำตอบ (Retrieval & LLM Generation)

กระบวนการค้นหาและตอบคำถาม (RAG Query Execution Flow)
rag_service.py & chat.py

ลำดับการทำงานเมื่อมีคำถามเข้ามา (Query Execution Steps):

  1. Step 1: กรองคำทักทายและคำหยาบคาย (Fast-Path Check) * ถ้าเป็นคำทักทาย (สวัสดี, hello) ตอบข้อความทักทายทันที ไม่เรียกโมเดล AI * ถ้าเป็นคำถามด่วนที่ตรงกับ FAQ หน้าแรก ส่งคำตอบตายตัวกลับทันที
  2. Step 2: การค้นหาแบบผสมผสาน (Hybrid Retrieval) * ค้นหา Vector Similarity ใน ChromaDB ได้อันดับ Rank(dense) * ค้นหา Keyword Matching ใน BM25 ได้อันดับ Rank(bm25)
  3. Step 3: การจัดอันดับด้วย Weighted RRF (Reciprocal Rank Fusion)
    Score = (0.4 / (60 + Rank_dense)) + (0.6 / (60 + Rank_bm25))
    * ให้ค่าน้ำหนัก BM25 = 0.6 และ Dense = 0.4 เพื่อความแม่นยำสูงสุดในข้อความภาษาไทยที่มีคำเฉพาะทาง
  4. Step 4: ประกอบ Context และส่งคำขอไปยัง LLM * ดึง Chunks ที่ได้คะแนนสูงสุด `top_k` (ค่าเริ่มต้น 3 ชิ้น) * ประกอบเข้ากับ System Prompt ของโรงพยาบาล * ยิงคำขอแบบ Async ผ่าน httpx ไปยัง OpenRouter API (โมเดล Google Gemma)
  5. Step 5: ส่งคืนคำตอบพร้อมเอกสารอ้างอิง * ส่งคำตอบให้ผู้ใช้ พร้อมแนบข้อมูลเอกสารและเลขหน้า PDF ต้นฉบับ * บันทึกประวัติคำถาม-คำตอบลงฐานข้อมูล history ใน Background
